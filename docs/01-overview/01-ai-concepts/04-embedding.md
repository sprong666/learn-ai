# 向量化（Embedding）

> 一句话解释：把文本变成数字的技术

## Embedding 是什么？

- **一句话解释**：把文本变成数字的技术。
- **通俗解释**：AI 的"翻译器"，把人类语言翻译成 AI 能懂的数字。

计算机根本不懂中文或英文，它只懂数字。Embedding 就是一个翻译过程：把人类的文字（或图片），转换成一串计算机能理解的数字列表（向量）。

:::note

很多人认为，向量化就像查字典：`{"苹果": 001, "香蕉": 002}`。如果是这样，那么 001 和 002 在数学上没有任何关系，计算机依然不知道它们都是水果。

实际上**向量化是上下文相关的动态浮点数矩阵**，多维数组。

:::

## 为什么向量化很重要

为了理解向量化为什么重要，我们需要对比两种检索逻辑：传统关键词匹配与现代语义向量检索。

**传统检索（图书馆索引）**：想象你去图书馆找一本关于"水果"的书。如果你只搜索"苹果"这个词，传统的检索系统就像一个只会死板的图书管理员。他会去目录卡里找带有"苹果"两个字的卡片。

- 如果目录上写的是"Red Delicious"（红蛇果），他就找不到，因为字面不完全匹配。
- 如果文档里写的是"一种富含维生素的圆形果实"，他也找不到，因为完全没有关键词重叠。

这就是传统计算机处理文本的方式：只看字面，不懂意思。

**向量检索（超市货架布局）**：现在，想象你在逛一个设计得非常科学的超市。

- 当你站在"啤酒"货架前，你会发现旁边通常是"花生米"或"薯片"，因为它们经常被一起消费（关联性强）。
- 而"洗发水"则离这里十万八千里，虽然它们都是商品，但在功能属性上完全不搭边。

在这个超市里，每个商品都有一个隐形的"坐标值"：

- "啤酒"的坐标可能是 `[酒水区, A通道, 3层]`
- "花生"的坐标可能是 `[零食区, B通道, 1层]`

虽然它们名字不同，但在数学空间上，它们的距离非常近。向量化就是把文字变成这种"超市坐标"的技术。当 AI 需要理解"我想喝点配下酒菜的东西"时，它不需要匹配"花生"这两个字，它只需要在坐标空间里寻找离"酒"最近的区域，就能精准地推荐给你花生米。

## 向量化执行机制

向量化并不是简单的"查字典"，而是一个通过海量数据训练出来的数学映射过程。我们可以将其拆解为三个核心步骤：

### 1. 离散文本切分

计算机无法直接处理一整句话，它首先需要像切香肠一样，把文本切成最小的单位，叫做 Token（词元）。

- 输入："人工智能改变世界"
- 切分：`["人工", "智能", "改变", "世界"]`

这是将人类模糊的语言转化为计算机可处理的数字序列的第一步。

### 2. 特征空间映射

这是最神奇的一步。模型（如 BERT 或 Word2Vec）会将每一个 Token 也就是每一个词，映射到一个拥有几百甚至几千个维度的向量中。

- 不要被"高维"吓跑，你可以把它理解为一个超详细的体检报告。
- 普通的坐标只有 X、Y、Z 三个参数。
- 而词向量的坐标可能有 768 个参数。第 1 个参数代表"它是生物吗？"，第 2 个参数代表"它是动词吗？"，第 3 个参数代表"它是褒义词吗？"……

通过这 768 个参数的精确描述，"国王"这个词的向量，减去"男人"的向量，再加上"女人"的向量，结果会惊人地落在"女王"的向量附近。这就是向量空间蕴含的逻辑力量。

### 3. 语义距离计算

有了坐标，我们就能计算距离。在 AI 领域，我们通常使用**余弦相似度**来衡量两个词的关系紧密度。

- 数值越接近 1，说明两个词在语义上越像"双胞胎"。
- 数值越接近 0，说明两个词就像"石头和香蕉"，毫无关系。

通过这一步，搜索引擎不再问你"有没有包含这个词"，而是问你"这句话的意思，和数据库里哪段话的意思最接近"。

## 应用场景

### 场景 1：语义搜索 / 知识库检索（RAG 的底座）

流程：

1. 把公司文档切成 chunk
2. 每个 chunk → `embed()` → 存入向量数据库（Milvus / Qdrant / pgvector…）
3. 用户提问 → `embed(query)` → 最近邻搜索（ANN，近似最近邻）
4. 把最相关 chunk 塞进 prompt → LLM 生成答案

| | 关键词搜索 | 向量语义搜索 |
| --- | --- | --- |
| 匹配依据 | 字面重合 | 语义距离 |
| 能否跨表述 | ❌ "没声音"≠"音频故障" | ✅ 距离近就能召回 |
| 可维护 | 靠 synonym/规则堆 | 靠向量空间泛化 |

### 场景 2：智能客服 / 工单聚类

- 把海量用户消息向量化
- 用**余弦相似度 / 聚类（HDBSCAN/K-Means）**自动归簇
- "进不去系统 / 登录失败 / 密码报错"自然聚到一起 → 路由到技术支持队列
- 还能做 duplicate detection（重复工单合并）
