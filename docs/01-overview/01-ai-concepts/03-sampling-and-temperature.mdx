# 温度与采样参数

> Temperature、Top-p 等参数如何控制模型生成的随机性

import TemperatureDemo from '@site/src/components/TemperatureDemo';

## 本章目标

- 理解模型生成文本时的"概率分布"本质
- 掌握 Temperature（温度）的作用与取值建议
- 了解 Top-p、Top-k 等其他采样参数
- 能根据任务类型选择合适的参数组合

## 一、生成 = 从概率分布中抽样

模型每次只生成一个 Token。在输出之前，它先对所有候选 Token（约 5 万+）计算一个**概率分布**，然后从中选出一个：

```
输入：中国的首都是

候选 Token 概率分布：
  "北京"   → 82%
  "中国"   →  7%
  "一座"   →  4%
  "位于"   →  2%
  ……（其余几万个 Token 分享剩余概率）
```

**采样参数决定的就是"怎么从这个分布里选"**：是永远选概率最高的，还是按概率随机抽。同样的输入，参数不同，输出就不同。

## 二、Temperature（温度）

温度控制分布的"尖锐程度"，是最重要的采样参数：

- **低温（→ 0）**：分布被"锐化"，高概率 Token 几乎必中，输出确定、稳定、保守
- **高温（→ 1+）**：分布被"抹平"，低概率 Token 也有机会被选中，输出多样、意外、有创造性

用一个"中国的首都是哪里？"的例子直观感受不同温度下的回答差异：

| 温度 | 典型输出 | 风格 |
| --- | --- | --- |
| 0.0 | 中国的首都是北京。 | 每次都一字不差 |
| 0.7 | 中国的首都是北京，一座有着三千多年建城史的古都。 | 稳定但有余地 |
| 1.0 | 中国的首都是美丽的历史名城北京。 | 表述开始多变 |

### 取值建议

| 温度区间 | 特点 | 适用场景 |
| --- | --- | --- |
| 0.0 ~ 0.3 | 确定性强、可复现 | 代码生成、数据抽取、分类、事实问答、数学 |
| 0.4 ~ 0.7 | 平衡稳定与多样 | 日常问答、总结、翻译、普通写作 |
| 0.7 ~ 1.0+ | 多样、有创意 | 创意写作、头脑风暴、起名、营销文案 |

经验法则：**要"对"就用低温，要"新"就用高温**。调试 Prompt 时也建议先用温度 0——输出可复现，才好对比不同提示词的效果。

## 三、Top-p（核采样）

Top-p（又称 nucleus sampling，核采样）换了一个思路控制随机性：**只在累计概率达到 p 的最小候选集内采样**。

- `top_p = 0.9`：按概率从高到低排序，取到累计 90% 为止（可能是 3 个词，也可能是 300 个词），只在其中随机选
- 作用类似温度，但更"自适应"：分布集中时候选少，分布平均时候选多

**实践建议**：Temperature 和 Top-p 都调节随机性，一般**只调其中一个**，同时大幅调两个会让行为难以预测。很多产品（如 ChatGPT 网页版）不暴露这些参数，但调用 API 时它们都可用。

## 四、Top-K

Top-K 是 Top-p 的简化版：**无论概率分布如何，永远只在概率最高的 K 个候选里选**。

- `top_k = 50`：只看前 50 名，其余全部排除
- 缺点是不自适应：分布很集中时 50 个太多，分布很平均时 50 个又可能不够

三者的关系：

```
全部候选（5万+）
  └─ Top-K：先砍到 K 个
       └─ Top-p：再按累计概率筛选
            └─ Temperature：调整剩余候选的选中概率
                 └─ 抽出最终 Token
```

## 五、其他相关参数

| 参数 | 作用 |
| --- | --- |
| Frequency Penalty | 降低已出现 Token 的概率，减少用词重复 |
| Presence Penalty | 只要出现过就惩罚，鼓励引入新话题 |
| Max Tokens | 限制回答最大长度，防止挤占上下文窗口（见 [上下文窗口](02-context-window.md)） |
| Stop Sequences | 遇到指定字符串就停止生成 |

## 六、常见误区

- **"温度越高模型越聪明"** —— 错。温度只影响随机性，不影响能力；高温反而可能降低事实类任务准确率
- **"温度 0 就一定准确"** —— 错。低温只是让输出稳定，该错还是错（见幻觉相关讨论）
- **"参数要调到最优才能用"** —— 大多数任务用默认值即可，只有在输出"太死板"或"太飘"时才需要动

## 小结

- 模型生成 = 对候选 Token 的概率分布抽样，采样参数决定抽样策略
- Temperature 控制随机性：低温求稳，高温求新；调 Prompt 时先用 0
- Top-p / Top-K 是候选集筛选器，与 Temperature 二选一调整即可
- 任务类型决定参数：代码/抽取用低温，创意写作用高温
