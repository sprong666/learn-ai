## 一、什么是大语言模型（LLM）

大语言模型就是"读了互联网上几乎所有文字"的 AI。它通过分析海量文本，学会了人类语言的规律，从而能**理解你的问题**并**生成流畅的回答**。

> **类比理解**：想象一个人读了一千万本书，虽然他不一定"理解"每本书的含义，但他能根据上下文，流畅地写出类似的内容。这就是大模型的工作原理。

模型的"大"，体现在两方面：

- **参数量大**：从几十亿（7B）到上万亿（1.6T）参数
- **训练数据量大**：数万亿 Token 的文本语料

主流模型代表：GPT（OpenAI）、Claude（Anthropic）、Gemini（Google）、DeepSeek、Qwen（阿里）、GLM（智谱）等，分开源与闭源两条路线。

模型本质是在做**下一个 Token 预测**：给它前文，它预测最可能的下一个 Token，如此循环生成整段回答。

## 二、Token：AI 世界的"基本单位"

### 2.1 为什么需要 Token？

先做个小实验：请你快速念出这几个字——**薛、赜、罅、龘**。

是不是愣了几秒？但如果它们出现在词语里（"薛定谔"、"赜探"），你可能瞬间就能念出来。

这就是人脑的"偷懒机制"：我们习惯把**有意义的词语作为整体**处理，而不是一个字一个字地抠。比如"今天天气不错"：

- 按字处理：需要处理 6 个部分，还要理解它们如何组合
- 按词处理："今天" + "天气" + "不错"，只需处理 3 个有意义的单元

**AI 模仿了这种机制**——这就是 Token 存在的根本原因：它是 AI 世界的"信息积木"，让大模型用更高效的方式处理文字。

### 2.2 Token 到底是什么？

**Token 是大模型理解和生成文字的最小单位。**

当你输入一段话，模型并不是直接"看懂"文字，而是先由分词器（Tokenizer）把文字切成一个个 Token。切出来的可能是：

- 一个汉字：「鸡」
- 两个汉字：「苹果」
- 三个汉字：「孙悟空」
- 一个标点：「。」
- 一个单词：「apple」
- 半个单词：「ing」

**为什么这么不统一？** 因为分词器统计海量文字后发现，有些组合经常一起出现，打包处理更高效。就像点外卖，单点米饭 + 青菜 + 肉，不如直接点"套餐"方便。

### 2.3 分词器是怎么工作的？

分词器的训练过程，就是"找规律、建词表"的过程：

1. **统计高频组合**：分析大量文本，发现哪些字/字母经常一起出现
   - 「苹」「果」总是成双成对 → 打包成一个 Token，编号 12345
   - 「鸡」字到处乱窜，能搭配各种字 → 单独一个 Token
   - 英文「i」「n」「g」经常连在一起 → 打包成 Token「ing」
2. **构建 Token 词表**：经过海量统计，得到包含 5 万、10 万甚至更多 Token 的词表
3. **转换与编码**：
   - 输入阶段：分词器把文字切成 Token，转成对应的数字编号
   - 计算阶段：模型只需处理这些数字
   - 输出阶段：再把数字编号转换回文字

> **类比餐厅分工**：分词器是"切配工"，负责把食材切成合适大小；大模型是"主厨"，负责烹饪。切配工刀工越好，主厨越省力，出菜越快。

### 2.4 DeepSeek 分词实测：切法由频率决定

同一个词在不同模型中的 Token 数可能不同，因为**训练数据不同，对"什么算高频"的判断也不同**。

下面是用 DeepSeek 分词器（`deepseek-ai/deepseek-coder-1.3b-base`）**实际运行**的切分结果：

| 输入文本 | Token 数 | 切分结果 | 说明 |
| --- | --- | --- | --- |
| 人工智能改变世界 | 3 | `人工智能` `改变` `世界` | 高频词直接打包 |
| 今天天气不错 | 3 | `今天` `天气` `不错` | 按词切分，和人脑习惯一致 |
| 鸡蛋 | 1 | `鸡蛋` | 训练语料中高频词 |
| 鸭蛋 | 2 | `鸭` `蛋` | 出现频率低，按字切分 |
| 哈哈 | 1 | `哈哈` | 高频组合 |
| 哈哈哈哈哈（5 个哈） | 3 | `哈哈` `哈哈` `哈` | 超出高频范围，拆开重切 |
| apple | 1 | `apple` | 完整单词 |
| Artificial Intelligence | 4 | `Art` `ificial` ` Int` `elligence` | 英文按子词（词根/词缀）切分 |

可以看到"打包"完全由**语料中的出现频率**决定，没有任何语义判断——"鸡蛋"是 1 个 Token 只是因为它在语料里出现得多，"鸭蛋"被拆开也不是因为模型认识鸡不认识鸭。

## 三、Token 的实战价值

### 3.1 Token 数量 = 计算量 = 费用

模型生成内容，本质是预测"下一个 Token 最可能是哪个"。处理的 Token 越多，计算量越大，消耗的 GPU 算力越多。

```
输入 1000 Token 的问题 + 生成 500 Token 的回答 = 1500 Token
若每 Token 消耗 0.001 元，这次对话就是 1.5 元
```

### 3.2 中英文消耗差异

由于分词器以英文语料为主设计，**中文通常更"费 Token"**：

- 中文「人工智能」→ 约 4 个 Token
- 英文「Artificial Intelligence」→ 约 2-3 个 Token

同样语义，中文提问可能比英文多花 20-30% 的 Token 费用。

### 3.3 Token 与上下文窗口

每个模型有"上下文窗口"上限（一次能处理的 Token 总数），这决定了：

- 一次对话能塞进多少资料
- 多轮对话能"记住"多久之前的内容

详见 [上下文窗口](02-context-window.md)。

### 3.4 优化 Token 消耗的实用建议

1. **精简 Prompt**：避免冗余描述，用最简洁的语言表达需求
2. **善用上下文**：多轮对话中避免重复已说过的内容
3. **合理设置长度限制**：不需要长回答时，明确告诉模型"用 100 字回答"
4. **英文场景优先英文**：内容本身是英文时，直接用英文提问更省 Token

## 四、Token 机制的局限与趋势

| 局限 | 说明 |
| --- | --- |
| 语言不公平 | 中文、日文等字符密度高的语言 Token 消耗远高于英文 |
| 不真正理解语义 | 分词只靠频率统计，"薛定谔"被打包成一个 Token，但分词器并不知道它是物理学概念 |

未来趋势：多语言均衡分词、语义感知分词（结合上下文而非仅频率统计）、动态 Token 粒度。

## 小结

- LLM = 海量数据训练出的"下一个 Token 预测器"
- Token 是模型处理文字的最小单位，由分词器按高频统计切分，粒度不固定且因模型而异
- Token 数量决定**计费**（数量 = 计算量）、**上下文上限**（窗口大小）和**速度**（逐 Token 生成）
- 大模型生成内容像"打字"，正是因为它一个 Token 一个 Token 地输出
