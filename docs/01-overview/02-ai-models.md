# 理解 AI 模型

> 从"模型是什么"出发，建立对 AI 模型的直觉认识：结构、训练、推理与局限

## 本章目标

- 理解什么是 AI 模型，它和传统程序有什么区别
- 了解 Transformer 与 LLM 的基本工作原理
- 理解预训练、微调、对齐等训练阶段
- 理解推理过程（Next Token Prediction）与采样参数
- 建立"模型能力边界"的正确预期

## 一、什么是 AI 模型

传统程序是**人写规则、机器执行**；AI 模型是**机器从数据中学出规则**：

```
传统程序：  数据 + 规则  →  答案
机器学习：  数据 + 答案  →  规则（模型）
```

一个"模型"本质上是一堆**带参数的数学函数**（现代大模型通常是 Transformer 神经网络）。
所谓"训练"，就是不断调整参数，使得模型在大量样本上的预测误差最小。

- 参数量：模型里可调节的权重数量，如 7B = 70 亿参数
- 参数越多、数据越多，模型能学到的模式通常越丰富（Scaling Law）

## 二、Transformer：现代大模型的基石

2017 年 Google 提出的 Transformer 架构，核心是 **自注意力机制（Self-Attention）**：

1. **分词（Tokenize）**：文本被切成 Token（词、子词或字符片段），并映射为向量
2. **注意力**：每个 Token 会"环顾"上下文中的其他 Token，计算相关性权重，从而理解"它"指代谁、"银行"在取钱还是河边的语境
3. **多层堆叠**：几十到上百层注意力 + 前馈网络，逐层抽象出从语法到语义再到知识的表示
4. **输出**：对下一个 Token 的概率分布

关键特性：**并行计算**（训练快）+ **长程依赖**（能关联远距离的信息）。

## 三、LLM 是如何训练出来的

以一个对话大模型为例，通常分三个阶段：

| 阶段 | 做什么 | 产出 |
| --- | --- | --- |
| 预训练（Pre-training） | 在海量文本上做"预测下一个 Token"，学到语言、知识与推理模式 | 基座模型（Base Model） |
| 微调（SFT） | 用高质量"指令-回答"样本教模型按指令回答 | 指令模型 |
| 对齐（RLHF / DPO 等） | 用人类偏好反馈，让回答更有用、诚实、无害 | 对话模型（Chat Model） |

直观理解：预训练是"读书"，微调是"做题"，对齐是"学做人"。

## 四、推理：模型如何生成内容

LLM 一次只生成**一个 Token**，生成一个长回答就是不断循环：

```
输入 → 模型 → 下一个 Token 的概率分布 → 采样出一个 Token → 拼回输入 → 重复
```

采样相关参数：

- **Temperature（温度）**：控制随机性。越低越确定（适合写代码、抽取），越高越发散（适合创意写作）
- **Top-p / Top-k**：只在概率最高的一小批候选 Token 里采样
- **上下文窗口（Context Window）**：模型一次能"看到"的最大 Token 数，超出就需要截断或压缩

工程上的两种推理阶段：

- **Prefill（预填充）**：并行处理你的全部输入，产出第一个 Token
- **Decode（解码）**：逐 Token 生成，受显存带宽限制，所以"越写越慢体感"来自这里

## 五、模型的局限：建立正确预期

理解模型"会犯什么错"和"会什么"同样重要：

| 局限 | 原因 | 应对 |
| --- | --- | --- |
| 幻觉（编造事实） | 模型学的是概率分布，不是事实数据库 | 要求引用来源、RAG 检索增强、让模型承认不知道 |
| 知识截止 | 训练数据有截止日期 | 联网搜索、文档注入 |
| 上下文遗忘 | 窗口有限、长上下文中间信息利用率低（Lost in the Middle） | 关键信息放头尾、压缩与摘要、外部记忆 |
| 数学与精确计算弱 | 模型是概率系统，不是计算器 | 调用工具（代码解释器、计算器） |
| 提示敏感 | 同一问题换个说法结果不同 | 提示词工程（见 [提示词工程](03-prompt-engineering.md)） |

## 六、小结

- 模型 = 从数据中学出参数的函数；现代大模型 = Transformer + 海量数据 + 巨量参数
- 训练三部曲：预训练 → 微调 → 对齐
- 推理 = 逐 Token 的概率采样，温度等参数控制随机性
- 模型不是数据库也不是计算器，工程上要用工具、检索和好的提示词来补足它的短板
