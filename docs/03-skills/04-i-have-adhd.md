# i-have-adhd SKILL

> 来源：[ayghri/i-have-adhd](https://github.com/ayghri/i-have-adhd/blob/main/skills/i-have-adhd/SKILL.md)（MIT 许可）

## 本章目标

- 理解这个 SKILL 解决的核心问题：AI 的回答往往"信息完整但难以执行"，对注意力资源稀缺的读者尤其致命。
- 学习它如何把"可访问性需求"转化为一组可执行、可自检的输出规则。
- 借鉴其 SKILL 编写技巧：持久化声明、Bad/Good 对照、"何时可以打破规则"的例外条款。

## 正文

### 1. SKILL 定位

| 属性 | 内容 |
| --- | --- |
| name | `i-have-adhd` |
| 触发方式 | 仅手动调用（`disable-model-invocation: true`），用户输入 `/i-have-adhd` 开启 |
| 关闭方式 | 用户说 "stop adhd mode" 或 "normal mode" |
| 类别 | Output Style（输出风格），而非工具编排类 SKILL |

关键设计决策：`disable-model-invocation: true`。这是一个**用户主动选择的风格偏好**，不该由模型猜测触发——用户说开就开，说关才关。它同时通过 frontmatter `description` 向模型声明"会话内持续生效"。

### 2. 问题建模：五条认知事实

SKILL 开头不写空泛目标，而是给出五条驱动所有规则的认知事实，让模型理解"为什么"而不仅是"做什么"：

1. **工作记忆小** —— 不在屏幕上的东西等于不存在，不能要求读者"记住 X"。
2. **知道 ≠ 做到** —— "懂了"和"做了"之间的摩擦力正是工作流失的地方。
3. **启动最难** —— 第一个动作必须显而易见、足够小、现在就能做。
4. **时间感知失真** —— "有点工作量"和"几小时"在读者脑中注册成同一个东西，模糊的估计无效。
5. **多巴胺稀缺** —— 可见的进展才有意义，被埋没的成果不会被感知。

### 3. 十条输出规则

| # | 规则 | 一句话要点 |
| --- | --- | --- |
| 1 | 先给下一步动作 | 第一行就是能做的事，不是背景、不是计划 |
| 2 | 多步任务编号 | 每步一个有界动作，一个步骤里不超过一次 "and then" |
| 3 | 以一个具体下一步结尾 | 命名一件两分钟内能完成的事，哪怕是"打开那个文件" |
| 4 | 压制岔路话题 | 先完成主线，次要问题作为独立问题单独提出 |
| 5 | 每轮重述状态 | "第 3 步，共 5 步" 不能指望读者跨消息记住 |
| 6 | 给具体时间估计 | 用具体单位（"约 15 分钟，如果测试已覆盖"） |
| 7 | 让完成的工作可见 | 用具体术语展示"现在什么能用了" |
| 8 | 错误用平实语气 | 不说 "Uh oh"，直接说原因和修复 |
| 9 | 列表上限 5 项 | 分组排序，但只约束展示、不约束分析完整性 |
| 10 | 无开场白/无复述/无客套结束语 | 从答案开始，答案说完就结束 |

规则 9 是一个容易被忽略的精妙设计：它明确区分**展示层**与**分析层**——"绝不能因完整性而遗漏相关项，本规则只约束呈现方式"。这避免了风格规则侵蚀任务质量。

### 4. 例外条款：何时打破规则

这是本文档最值得借鉴的部分。一条风格规则如果绝对化，必然在真实场景中产出错误答案。SKILL 列出六种覆盖默认行为的情形：

1. 用户要求"解释/逐步讲解" → 完整展开，只保留"无开场白"的约束。
2. 破坏性操作（`rm -rf`、强推、schema 迁移） → 先确认。**安全优先于简洁**。
3. 调试死循环（连续三轮"还是坏的"） → 停止改代码，说出可能错误的假设，提一个诊断性问题。
4. 请求存在真实歧义 → 一个简短的澄清问题胜过猜测重写。
5. 规则与任务冲突 → 任务赢，形式让步。例："有哪些选项"就该给 2–4 个带权衡的选项，而不是一条路径。
6. 规则与 harness 冲突 → 系统提示优先级高于本 SKILL。

### 5. 发送前自检清单

SKILL 以一个可操作的"pre-send check"收尾，要求发送前删除：

1. 宣布"我将要做 X"的第一句
2. "还需要什么吗"或复述刚发生之事的最后一句
3. 任何 "by the way" 插叙
4. 不携带信息的模糊副词（但保留表达真实不确定性的措辞）
5. 习语和比喻（"circle back" → 换成字面上的动作）

最终验收标准一句话概括：**如果读者只看第一行和最后一行，能知道 (a) 下一步做什么、(b) 刚发生了什么，就可以发送。**

### 6. 可借鉴的 SKILL 编写技巧

- **持久化声明**（Persistence 段）：明确规则"跨轮次、跨话题持续生效，拿不准时视为生效"，解决风格指令几轮后失效的常见问题。
- **Bad/Good 对照**：每条规则都配反例和正例，模型模仿的精度远高于抽象描述。
- **先给 why 再给 what**：五条认知事实让模型能泛化到规则未覆盖的场景。
- **显式例外清单**：把"什么时候别听话"写进文档，比让模型临场自行判断更可靠。
- **收尾自检**：把风格约束压缩成一个发送前的二元判断，便于执行。

## 小结

- `i-have-adhd` 是一个纯输出风格类 SKILL：不调用工具、不编排流程，只重塑回答的**形态**——行动优先、步骤编号、状态重述、去客套。
- 它的工程质量体现在三处：手动开关的调用模型、显式的例外条款、发送前自检清单。
- 核心洞见适用于所有写作：**读者只看首尾两行也应该能获得全部关键信息**。
