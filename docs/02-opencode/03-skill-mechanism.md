# OpenCode SKILL 机制

## 一、概述

### 1.1 什么是 Skill

Skill 是 OpenCode 提供的**可复用、按需加载的专业知识包**，通过标准 `SKILL.md` 文件定义，AI Agent 会根据用户任务语义自动识别、匹配并加载对应技能，用于封装团队业务规范、技术流程、指标定义、代码标准等私有专业知识。

### 1.2 设计初衷与解决痛点

原生 Claude/OpenCode 每次对话会话独立，模型无团队专属上下文，存在明显缺陷：

1. 不了解项目数据表结构、业务指标定义；
2. 不清楚团队过滤规则、编码规范、通用查询模板；
3. 每次对话都需要重复交代业务规则，大量消耗 Token。

Skill 通过**渐进式分层加载**机制，仅在任务匹配时注入对应专业知识，解决上下文冗余、信息不一致、知识无法跨项目复用的问题。

### 1.3 核心优势

1. **按需加载**：不常驻上下文，大幅节省 Token；
2. **跨项目复用**：区分项目级/全局级技能，团队统一标准；
3. **分层轻量化**：三层渐进披露，只加载当前任务所需内容；
4. **全平台兼容**：支持 Claude Code、OpenCode CLI、IDE 插件、API；
5. **精细化权限管控**：支持允许/询问/拒绝三种访问策略，支持通配符批量配置；
6. **模块化维护**：核心逻辑与详细参考文档分离，便于迭代更新。

## 二、核心设计理念：渐进式披露（三层加载模型）

Skill 不会一次性把全部文档塞入上下文，分为三层逐级加载，平衡信息完整度与上下文开销：

1. **第一层：name + description（永久可见）** 仅技能标识与能力描述，用于 Agent 判断是否需要加载该技能，轻量化、常驻可用。
2. **第二层：SKILL.md 主体（匹配任务时加载）** 存储核心工作流程、通用规则、标准模板、核心计算公式，是技能主体。
3. **第三层：references/ 参考文档（按需加载）** 存放大篇幅详细资料（表结构、完整示例、细分业务文档），仅当需要深度细节时读取。

## 三、Skill vs CLAUDE.md 核心对比

| 对比维度   | CLAUDE.md                     | Skill                   |
| ------ | ----------------------------- | ----------------------- |
| 加载时机   | 会话**始终加载**到上下文                | 任务语义匹配后**按需加载**         |
| 适用范围   | 仅当前项目，无法全局共享                  | 支持项目级 + 全局级，跨项目复用       |
| 内容承载   | 纯 Markdown，仅项目基础规范            | Markdown + 代码 + 参考资源目录  |
| 平台支持   | 仅 Claude Code / OpenCode Code | Claude.ai、Code、API 全平台  |
| 典型使用场景 | 项目专属编码规范、本地命令约定               | 通用专业领域知识、业务分析流程、标准化工具流程 |

### 选用原则

- 仅当前项目生效、简单本地规范 → 使用 `CLAUDE.md`
- 团队通用、可跨项目复用的专业流程、业务指标、工具模板 → 使用 Skill

## 四、Skill 目录结构规范

### 4.1 基础最简结构

每个技能独立文件夹，内部必须存在**全大写**的 `SKILL.md`：

```
.opencode/
└── skill/
    └── code-review/        # 技能名称目录
        └── SKILL.md         # 核心定义文件（文件名强制大写）
```

### 4.2 推荐完整工程结构（生产环境）

将详细文档抽离至 `references` 目录，保持 SKILL.md 精简：

```
.opencode/
└── skill/
    └── sql-analysis/
        ├── SKILL.md              # 主流程、核心规则、计算公式
        └── references/           # 详细参考资料（按需读取）
            ├── finance.md        # 财务数据表结构
            ├── product.md        # 产品层数据表
            └── examples.md       # 标准查询示例
```

### 4.3 支持嵌套目录

目录支持多层嵌套，技能名称以 `SKILL.md` 内 frontmatter 的 `name` 为准，不受文件夹层级影响：

```
.opencode/
└── skill/
    └── audit/
        └── security/
            └── SKILL.md
```

## 五、Skill 检索路径（项目级 + 全局级 + Claude 兼容）

OpenCode 启动时自动扫描以下全部路径，按优先级遍历（项目路径覆盖全局路径）：

|路径|生效范围|说明|
|---|---|---|
|`.opencode/skill/<name>/SKILL.md`|当前项目|OpenCode 原生项目技能|
|`.opencode/skills/<name>/SKILL.md`|当前项目|复数目录兼容写法|
|`~/.config/opencode/skill/<name>/SKILL.md`|本机全局|所有项目通用全局技能|
|`.claude/skills/<name>/SKILL.md`|当前项目|Claude Code 兼容目录|
|`~/.claude/skills/<name>/SKILL.md`|本机全局|Claude 全局兼容目录|

### 自定义检索路径

通过环境变量 `OPENCODE_CONFIG_DIR` 追加自定义技能目录，适用于团队共享技能库：

```
# Linux/macOS
export OPENCODE_CONFIG_DIR="/team/shared/opencode-config"
```

OpenCode 会同时扫描默认全局目录 + 自定义配置目录下的技能。

## 六、SKILL.md 文件标准格式

### 6.1 强制 YAML Frontmatter（文件头部）

`name`、`description` 两个字段**必须填写**，否则技能无法被识别加载。

```

name: sql-analysis
description: |
  业务数据查询分析技能，用于收入、ARR、客户分群、产品使用数据分析。
  提供：公司数仓表结构、收入指标计算公式、标准过滤规则、SQL查询模板。
  适用：业务数据SQL查询、财务指标核算、营收报表生成。
  不适用：数据库DDL运维、SQL性能调优、通用SQL教学。

```

#### 字段说明

|字段|是否必填|规范与作用|
|---|---|---|
|name|是|技能唯一标识，命名规则：小写字母数字，单连字符分隔，不能以 `-` 首尾、无连续横杠，正则 `^[a-z0-9]+(-[a-z0-9]+)*$`|
|description|是|触发匹配核心依据，语义匹配而非关键词检索，需写明能力、提供资源、适用/不适用场景|
|license|否|开源协议标识|
|compatibility|否|平台兼容标记|
|metadata|否|自定义扩展键值对|

### 6.2 description 编写规范（关键：决定技能能否自动触发）

1. 劣质示例（模糊无法匹配）：

```
description: 处理数据查询
```

2. 标准模板（推荐）：

```
description: |
  【一句话核心能力】
  提供：包含的资源（表结构、公式、模板、规范）
  适用：触发场景1、场景2、场景3
  不适用：边界场景（避免误触发）
```

### 6.3 SKILL.md 正文编写规范

1. 仅存放**通用流程、核心规则、计算公式、标准化步骤**；
2. 详细数据表、海量示例、细分文档全部放入 `references/`；
3. 写明读取参考文件的路径指引，方便 Agent 按需加载详情。

### 6.4 完整可运行示例

```

name: sql-analysis
description: |
  用于分析业务数据：收入趋势、ARR 计算、客户分群、产品使用、销售管道。
  提供：公司表结构、指标定义公式、标准过滤器、常用查询模板。
  适用：需要写 SQL 分析业务数据、理解公司指标定义、查询数据仓库。
  不适用：数据库管理、DDL 操作、性能调优、通用 SQL 教学。

# SQL 业务分析技能
## 标准执行流程
1. 确认需求时间范围，默认取当年完整月份；
2. 优先读取现有报表看板，避免重复开发SQL；
3. 优先使用汇总表，禁止直接查询原始事件表；
4. 强制添加业务过滤条件，排除测试数据。

## 全局强制过滤规则
所有收入相关SQL必须添加：
WHERE account != 'Test'
AND month <= DATE_TRUNC(CURRENT_DATE(), MONTH)

## 核心指标计算
1. 月度收入转ARR：monthly_revenue * 12
2. 7日滚动年化收入：rolling_7d * 52

## 详细参考文档
如需完整表结构与案例，读取以下文件：
- 财务指标：references/finance.md
- 产品埋点：references/product.md
```

## 七、权限控制配置

### 7.1 三种权限策略

|权限值|行为效果|
|---|---|
|allow|任务匹配时自动加载，无需用户确认|
|ask|匹配后弹窗询问用户，确认后才加载|
|deny|技能对Agent完全隐藏，拒绝任何访问|

### 7.2 全局权限配置（opencode.json）

支持通配符批量匹配一组技能：

```
{
  "permission": {
    "skill": {
      "*": "allow",
      "pr-review": "allow",
      "internal-*": "deny",
      "experimental-*": "ask"
    }
  }
}
```

### 7.3 按独立 Agent 覆盖权限

为特定子代理单独配置技能访问权限，覆盖全局规则：

```
{
  "agent": {
    "finance-audit": {
      "permission": {
        "skill": {
          "internal-finance-*": "allow"
        }
      }
    }
  }
}
```

### 7.4 完全禁用 Skill 工具

不需要技能系统时，可在 Agent 配置中关闭 skill 工具，Agent 将无法识别、加载任何技能：

```
# SKILL.md / AGENTS.md frontmatter

tools:
  skill: false

```

## 八、Skill 发现与加载完整流程

1. **扫描阶段**：OpenCode 启动时遍历全部技能目录，提取所有技能 `name` + `description` 存入可用技能列表；
2. **语义匹配**：用户发送指令后，Agent 基于语义理解匹配描述，判断是否需要加载对应技能；
3. **权限校验**：读取 opencode.json 权限配置，校验该技能是否允许访问；
4. **分层加载**
    - 匹配成功且权限放行：加载第二层 `SKILL.md` 完整内容；
    - 任务需要深度细节时，主动读取第三层 `references/` 下的文档；
5. **上下文注入**：将技能内容注入当前会话上下文，按照团队规范输出结果。

## 九、常见故障排查（踩坑清单）

|故障现象|根因|解决方案|
|---|---|---|
|Skill 完全无法加载|文件名非全大写 `SKILL.md`|修改文件名为大写，区分大小写|
|技能不显示在可用列表|frontmatter 缺失 name / description|补充两个必填字段|
|任务匹配但不触发加载|description 描述过于模糊|补充明确能力、适用场景、边界限制|
|同名技能冲突覆盖|项目/全局多处定义同名技能|统一技能命名，查看日志覆盖警告|
|访问被拒绝|权限配置为 `deny`|修改 opencode.json 权限策略|
|目录无法识别|文件夹拼写错误|`skill/` / `skills/` 均支持，核对路径|

## 十、最佳实践

1. **技能粒度拆分**：单一技能只负责一类场景（如 `sql-analysis`、`code-review`、`git-release`），避免大而全；
2. **区分项目/全局技能**：项目独有规范放项目目录，团队通用标准放全局目录；
3. **精简 SKILL.md**：海量参考资料全部移入 `references`，减少基础加载Token；
4. **规范命名**：统一小写连字符命名，保持全平台兼容性；
5. **权限精细化管控**：内部涉密技能配置 `deny`，实验性功能配置 `ask`；
6. **搭配 MCP 工具**：Skill 定义流程规范，MCP 提供外部工具能力，二者联动构建完整自动化流程。
